2. COMMENT SE CONNECTER AUX VMs & VOIR LES FICHIERS DEPLOYES
--------------------------------------------------------------------------------
Connexion SSH (Mot de passe : P@ssWord) :
   ssh acadmin@192.168.38.102    # Pour VM2 (app1)
   ssh acadmin@192.168.38.103    # Pour VM3 (app2)
   ssh acadmin@192.168.38.101    # Pour VM1 (ctrl-proxy)

Emplacement des fichiers sur chaque VM (/opt/africacloud) :
   ls -la /opt/africacloud
   ls -la /opt/africacloud/public

Détail des fichiers présents dans /opt/africacloud :
   - /opt/africacloud/Dockerfile          -> Image Docker de l'application
   - /opt/africacloud/docker-compose.yml  -> Orchestration Docker Compose (restart: always)
   - /opt/africacloud/server.py           -> Serveur Web & API REST Python 3
   - /opt/africacloud/africacloud.db      -> Base de données SQLite active
   - /opt/africacloud/schema.sql          -> Script SQL de création des tables
   - /opt/africacloud/public/index.html   -> Interface Web (Mode Clair)
   - /opt/africacloud/public/style.css    -> Feuille de style CSS (Mode Clair)
   - /opt/africacloud/public/app.js       -> Logique Frontend (appels fetch API REST)

Pour afficher le code sur la VM :
   cat /opt/africacloud/server.py
   cat /opt/africacloud/schema.sql
   cat /opt/africacloud/public/index.html


3. COMMENT VERIFIER QUE LE SERVICE & LES PORTS FONCTIONNENT (SUR LES VMs)
--------------------------------------------------------------------------------
A) Vérifier l'état du service Systemd (doit afficher "active (running)") :
   sudo systemctl status africacloud

B) Redémarrer ou voir les journaux (logs) en direct :
   sudo systemctl restart africacloud
   sudo journalctl -u africacloud -n 30 --no-pager

C) Vérifier que les ports (8080, 80, 3000) sont bien en écoute :
   sudo ss -tulpn | grep python3

D) Vérifier le pare-feu UFW :
   sudo ufw status verbose


4. COMMENT TESTER L'API REST & LA BASE DE DONNEES EN LIGNE DE COMMANDE
--------------------------------------------------------------------------------
A) Tester l'état de santé (GET /api/health) :
   curl http://192.168.38.102:8080/api/health
   curl http://192.168.38.103:8080/api/health

B) Lister tous les incidents techniques depuis la BDD (GET /api/issues) :
   curl http://192.168.38.102:8080/api/issues

C) Créer un nouvel incident technique en BDD via l'API (POST /api/issues) :
   curl -X POST http://192.168.38.102:8080/api/issues \
     -H "Content-Type: application/json" \
     -d '{"title":"Test Jury API","category":"Réseau / VLAN","priority":"Haute","reporter":"Jury","description":"Vérification API REST"}'

D) Modifier le statut d'un incident (PUT /api/issues/1) :
   curl -X PUT http://192.168.38.102:8080/api/issues/1 \
     -H "Content-Type: application/json" \
     -d '{"status":"Résolu"}'

E) Inspecter directement le contenu de la base de données SQLite sur la VM :
   python3 -c "import sqlite3; conn=sqlite3.connect('/opt/africacloud/africacloud.db'); print(conn.execute('SELECT * FROM issues').fetchall())"


5. COMMANDES DOCKER & DOCKER COMPOSE (DANS /opt/africacloud)
--------------------------------------------------------------------------------
Afficher le Dockerfile et le docker-compose.yml sur la VM :
   cat /opt/africacloud/Dockerfile
   cat /opt/africacloud/docker-compose.yml

Construire et lancer le conteneur avec Docker / Docker Compose :
   cd /opt/africacloud
   sudo docker build -t africacloud-incidents:1.0 .
   sudo docker compose up -d
